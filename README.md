# 文フリ レジ（bunfree-pos）

文学フリマの物販ブースで使う、iPad向けのPOSレジ（PWA）です。現金とPayPay（お客様がQRコードを読んで支払う方式）の会計を記録できます。
インターネットにつながっていなくても使えます。データはその端末の中（IndexedDB）にだけ保存し、外部には送りません。

- 技術：React + TypeScript + Vite / Tailwind CSS / Dexie.js（IndexedDB）/ vite-plugin-pwa（Service Worker）
- 金額はすべて整数（円）で計算します
- 画面：会計（ホーム）／売上・履歴／在庫／商品設定／レジ開始・締め／バックアップ

---

## 1. 開発環境での起動（Mac）

Node.js 20 以上が必要です（このMacでは `~/.local/node` に v24 LTS を入れてあります）。

```bash
export PATH="$HOME/.local/node/bin:$PATH"   # ~/.local/node を使う場合
cd ~/Projects/bunfree-pos
npm install
npm run dev        # 開発サーバー http://localhost:5173
npm test           # 自動テスト（計算・会計・取消・在庫・レジ締め・バックアップ・CSV）
npm run build      # 本番ビルド（dist/ に出力）
npm run preview    # 本番ビルドを http://localhost:4173 で確認（Service Worker も動く）
```

アイコンを作り直すときは `node scripts/make-icons.mjs` を実行します。

## 2. iPadへの導入手順

iPadでオフラインのまま使うには、アプリを **HTTPS** で公開し、Safariで「ホーム画面に追加」する必要があります。
Macのローカルサーバーをそのまま開く方法では、iPadにオフライン用のデータが保存されません。

### 2-1. GitHub Pages で公開する

1. GitHubに新しいリポジトリ（例：`bunfree-pos`）を作り、このフォルダを push する
2. リポジトリの Settings → Pages → Build and deployment の Source を **GitHub Actions** にする
3. `main` ブランチに push すると、`.github/workflows/deploy.yml` がビルドして公開する
4. 公開URLは `https://<ユーザー名>.github.io/bunfree-pos/` になる

公開されるのはアプリのプログラムだけです。売上などのデータは各iPadの中にだけ保存され、GitHubには送られません。
URLを知っている人は誰でもアプリを開けますが、開いた人の端末には空のレジが表示されるだけです。

### 2-2. iPadにインストールする

1. iPadの **Safari** で公開URLを開く
2. 共有ボタン →「**ホーム画面に追加**」
3. ホーム画面のアイコンから起動する（以後はこのアイコンから使う）
4. 一度起動したら、機内モードにして起動・会計できることを確認する

> Safariのタブで開いたまま使うと、しばらく使わないうちにデータが消えることがあります。必ずホーム画面のアイコンから使ってください。

### 2-3. アプリを更新したとき

GitHubに push すると公開版が更新されます。iPadでは、オンライン状態でアプリを開くと自動的に新しい版に切り替わります（反映されない場合は一度アプリを閉じて開き直す）。
**イベント当日の朝は更新しない**ことをおすすめします。

## 3. 使い方

### イベント前（前日まで）

1. **商品設定**：商品名・販売単価・販売状態・表示順を確認する
2. **在庫**：「在庫を修正」で持ち込む数を入力する（理由：搬入）。在庫0の商品は売り切れ表示になり、売れません

### 営業開始

3. **レジ開始・締め** → 釣銭準備金（例：20000）を入力して「レジを開始」。開始するまで会計はできません

### 会計（ホーム画面）

4. 左の商品の「＋」で数量を入れる（カードを押しても1つ増えます）
5. 右のテンキー、または「ちょうど／1,000／2,000／5,000／10,000」で預かり金額を入れる
6. 「会計を確定」→ 完了画面にお預かりとお釣りが大きく出る →「次のお客様へ」

- 預かり金額が足りない、在庫が足りない、販売停止の商品が入っている場合は確定できません
- 確定ボタンを連打しても、会計は1件しか記録されません

### PayPayの会計

4. 商品と数量を入れる（現金と同じ）
5. お客様にQRコードを読んでもらい、お客様のスマホで合計金額を入力・支払いしてもらう
6. お客様のスマホに表示された **支払い金額** をテンキーで入力する（「ちょうど」でも可）
7. 赤い「**PayPay**」ボタンを押す → 在庫と売上に反映される

- 「PayPay」ボタンは、入力した金額が合計と **同じとき** だけ押せます。違う金額で支払われていた場合は、PayPay側で返金・支払いをやり直してもらってください
- PayPayの売上はレジの現金には入らないため、レジ締めの理論現金残高には含めません（締め画面に参考として表示します）
- PayPayの会計を取消した場合、返金は PayPay for Business のアプリ・管理画面から行います（レジの現金からは返しません）

### 会計の取消（打ち間違い・返品）

7. **売上・履歴** → 対象の会計の「取消」→ 理由を入力 →「取消して返金する」
   - 取消は **全額返金** として扱います。画面に出た金額をお客様に返してください
   - 売上集計から除外され、在庫が戻ります。履歴は「取消」として残り、削除はできません
   - 一部だけの返品は、会計全体を取消してから打ち直してください
   - 取消はレジ営業中のみ行えます

### 売上以外の現金の出し入れ

8. **レジ開始・締め** →「売上以外の入金・出金」に金額と理由を記録する（釣銭の追加、レジの現金からの備品購入など）

### 営業終了（レジ締め）

9. **レジ開始・締め** → 金種ごとの枚数を入れる → 実際の現金残高・現金差異・判定（一致／現金過剰／現金不足）を確認 →「レジ締めを確定」
10. **バックアップ** →「バックアップを書き出す」で JSON を保存する（下記）

翌日も販売する場合は、もう一度「レジを開始」します。

### レジ締めの計算方法

```
理論現金残高 = 釣銭準備金 + 現金売上 + 売上以外の入金 − 売上以外の出金 − 返金額
現金差異     = 実際の現金残高 − 理論現金残高
```

- 「現金売上」は、そのレジで受け取った **現金会計** の総額です（あとで取消された会計も含む）。PayPayの会計は含みません
- 「返金額」は、そのレジで取消した **現金会計** の返金額です
- そのため取消した会計は「売上に入って、返金で出る」形になり、二重に引かれることはありません
- 前日の会計を翌日に取消した場合、返金は **取消をした日のレジ** の現金から出たものとして計算します（締め済みの結果は変わりません）

## 4. バックアップと復元

| 操作 | 場所 | 内容 |
|---|---|---|
| 全データのバックアップ（JSON） | バックアップ | 商品・会計・在庫履歴・入出金・レジ締めをすべて1ファイルに書き出す |
| 復元 | バックアップ →「ファイルを選んで復元」 | 内容を検証し、確認画面のあとで **現在のデータをすべて置き換える** |
| 売上履歴CSV | 売上・履歴／バックアップ | 明細1行＝1レコード。取消も含み、ステータス列で区別 |
| 商品別売上CSV | 売上・履歴／バックアップ | 取消を除いた商品別の販売数量・売上金額 |
| レジ締め結果CSV | レジ開始・締め／バックアップ | 締めごとの理論・実際・差異・金種別枚数 |

- iPadでは書き出したファイルを「ファイル」アプリ（iCloud Drive など）に保存してください
- **レジ締めのあと、イベント終了時に必ずJSONを書き出してください。** iPadの故障・紛失・Safariのデータ消去に備えるためです
- CSVは文字化け防止のBOM付きUTF-8です。Excel・Numbersでそのまま開けます

## 5. 仕様メモ

- 会計確定時に、商品ID・商品名・販売単価・数量・小計を **スナップショット** として保存する。あとで価格や商品名を変えても過去の会計は変わらない
- 会計確定・在庫減算・在庫履歴の保存、および取消・在庫戻しは、それぞれ **1つのトランザクション** で処理する。途中で失敗した場合は何も保存されず、エラーを表示する
- 会計IDを画面側で発行し、同じIDの会計は2回保存しない（二重会計の防止）
- 画面に表示していた合計とデータベース上の価格が食い違う場合は確定しない
- 在庫画面では、在庫履歴から計算した在庫と現在庫を照合し、食い違えば警告を表示する
- 会計履歴・商品は削除できない（商品は販売停止にする）
- レジ（釣銭準備金〜締め）は同時に1つだけ開始できる

## 6. フォルダ構成

```
src/
  lib/       calc.ts（金額計算）, summary.ts（集計）, csv.ts, types.ts
  db/        db.ts（Dexieのスキーマ・初期商品）, ops.ts（会計・取消・在庫・レジ）, backup.ts
  screens/   Checkout, Sales, Inventory, Products, Register, Backup
  test/      pos.test.ts（自動テスト）
  ui.tsx     共通部品（ボタン・ダイアログ・エラー通知）
scripts/     make-icons.mjs（アイコン生成）
.github/workflows/deploy.yml   GitHub Pages への自動公開
```
